# Frontend Handoff Backend Contract

Use this document when a frontend repository needs to consume a backend generated by SpecForge.

## Goal

Start from:

- `specforge-runtime/outputs/<project-backend>/`

End at:

- a frontend team or another Codex session can log in
- discover routes
- import a ready Postman environment
- reuse deterministic demo credentials

## Treat These Files As The Handoff Surface

Inside:

- `specforge-runtime/outputs/<project-backend>/`

the frontend-facing delivery assets are:

- `logs/demo-access.yaml`
- `logs/api-smoke/postman-collection.json`
- `logs/api-smoke/postman-environment.json`
- `logs/api-smoke/curl-login-example.sh`
- `logs/api-smoke/invoke-login.ps1`
- `src/main/resources/sql/schema.sql`
- `src/main/resources/sql/demo-password-reset.sql`

## What Each Asset Means

- `logs/demo-access.yaml`
  - canonical login endpoint
  - deterministic demo usernames
  - deterministic demo passwords
  - startup and import hints

- `logs/api-smoke/postman-collection.json`
  - generated route inventory for smoke testing
  - business and auth endpoints already grouped for quick verification

- `logs/api-smoke/postman-environment.json`
  - default `baseUrl`
  - `username`
  - `password`
  - token placeholder variables for Postman chaining

- `logs/api-smoke/curl-login-example.sh`
  - shell login example for Linux or macOS

- `logs/api-smoke/invoke-login.ps1`
  - PowerShell login example for Windows

- `src/main/resources/sql/schema.sql`
  - baseline schema and seed data

- `src/main/resources/sql/demo-password-reset.sql`
  - deterministic password reset script for known demo credentials
  - safe to reapply before smoke testing when database state has drifted

## Deterministic Demo Accounts

The generated backend exports these stable smoke-test accounts:

- `Admin / Admin@123456`
- `User / User@123456`

The canonical login endpoint is:

- `/v1/authorize/login`

If login fails in a reused database, re-import:

1. `schema.sql`
2. `demo-password-reset.sql`

## Fastest Frontend Smoke Path

1. Start the generated backend.
2. Import `logs/api-smoke/postman-collection.json`.
3. Import `logs/api-smoke/postman-environment.json`.
4. Run the login request first.
5. Reuse the returned token for business route requests.
6. Use `logs/demo-access.yaml` as the human-readable reference if anything is unclear.

## Handoff Rule For Another Codex Session

If another Codex session is asked to build or connect a frontend, tell it to read:

- `README.md`
- `WORKSPACE_LAYOUT.md`
- `specforge-runtime/docs/SUPER_QUICKSTART.md`
- `specforge-runtime/docs/FRONTEND_HANDOFF_BACKEND_CONTRACT.md`

and treat:

- `specforge-runtime/outputs/<project-backend>/`

as the only final backend delivery surface.

## Success Rule

For frontend handoff, accept the backend as ready only if:

- `logs/delivery-validation.yaml` says `status: PASS`
- `logs/sql-asset-validation.yaml` says `status: PASS`
- `logs/auth-surface-validation.yaml` says `status: PASS`
- `logs/demo-access.yaml` exists
- `logs/api-smoke/postman-environment.json` exists
- `src/main/resources/sql/demo-password-reset.sql` exists
