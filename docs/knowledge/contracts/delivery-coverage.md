# C-006 需求覆盖与模板复用实施合同

- 编号：C-006
- 状态：已验证
- 适用范围：新增真实项目；历史通用样板保留兼容
- 最近验证日期：2026-10-30
- 实现：[覆盖门禁](../../../specforge/coverage.py)
- 证据：[覆盖回归](../../../tests_core/test_requirement_coverage.py)

先从用户需求建立清单，再搜索模板实际源码、配置、SQL、前端调用与已有测试。知识库、模板目录说明或生成规则没有登记，不代表模板不具备该能力。

每项需求记录原始需要、直接复用 / 适配 / 业务定制的决定、理由、源码证据和 API / 浏览器 / 阶段验收项。生成副本的 `specforge/requirements.yaml` 随源码哈希进入交付包，`requirements.json` 记录逐项结果。新应用清单缺失、测试缺项、失败或清单哈希改变时不能发布；独立交付验收同样执行覆盖检查。

通用生成器不能覆盖的业务，由项目实现补齐。只有确实无法实现或成本需要取舍时才报告缺口；范围缩减必须有用户明确授权，不能自行改成“暂不支持”。多项目出现真实共性后再提取通用能力，不要求提前穷举模板能力或为每个项目新增永久 Python 应用模块。

本门禁验证声明的需求与执行证据一致，不是自动理解自然语言或形式化证明需求完整。需求本身的完整性仍须在实施前和交付前人工审阅，不能用测试条数代替审阅。模板适配补丁只应用于生成副本并保存原始字节哈希、修改后哈希及差异；不改源模板。


自动兼容例外仅限已有四个固定样板项目标识：device_borrow、book_lending、book_fields_v1、book_fields_v2。其他新项目即使未使用 application 扩展，也必须提供需求覆盖清单才能完成验收和发布；生成或 build-only 诊断不代表交付完成。


食谱的 12 项真实需求及独立部署结果见 [修复证据](../../core-evidence/recipe-reuse-fix.json)。

2026-10-30补充：覆盖清单同时用于源码和独立包验收。stages 使用两阶段共有的检查（如compose）；独立包不运行Maven/pnpm，不能声明它重新完成backend/frontend构建。源码构建由核心verify/package强制验证，不因清单未声明构建阶段而跳过。会议室接入暴露并修正此阶段声明错误，见[新项目记录](../../MEETING_PROJECT.md)。
