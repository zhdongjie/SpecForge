模板路径由调用者显式提供。本机使用外部 admin-platform 模板。复用 com.original 包、统一响应、认证、权限、分页和动态路由；仅在生成副本中增加业务扩展和 SQL，模板源目录保持不变。私有环境、密钥、运行数据与构建缓存不进入副本。


食谱应用在生成副本中设置模板显式 `frontend/src/appConfig.ts` 品牌名称，并增加专用业务 API 和页面。原模板认证、权限基础设施和源模板文件不改动。

## 发布模板与本地维护数据

2026-10-27 使用正式模板本地提交 `8a5e9cf` 完成食谱生成、完整需求覆盖和独立交付部署。输入仍显式指定模板路径，不把本机默认目录或旧验收工作副本当作唯一模板。

模板自身能力和使用方法以传入模板目录的 `docs/template/overview.md` 为入口；SpecForge知识库维护生成合同和适配限制。干净模板不需要包含本机验收脚本、历史报告、旧库迁移补丁或本地数据库版本记录表；生成与验收不得依赖这些本地资产。模板身份记录实际Git提交和输入文件哈希。

Windows/WSL 包装入口的本机默认值统一为已验证的独立模板仓库副本；核心CLI仍显式指定模板，其他环境通过 `-Template` 覆盖。直接运行命令见 [操作入口](../../CORE_V1.md)。不再要求用户另存一份可能失效的启动脚本。

2026-10-29食谱接入模板共享ImageValidationService；要求显式模板包含该服务，缺失即停止，不复制后备实现。业务仍决定公开/私有存储、访问权限和引用，能力接口权威说明在模板docs/template/files.md。实际职责和两项目回归见[复用审计](../../REUSE_COST_AUDIT.md)。
