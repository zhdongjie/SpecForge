# T-008 DATETIME 的业务时区与 JDBC 参数

- 编号：T-008
- 状态：已验证（源码及独立部署）
- 适用范围：当前模板 JDBC/MySQL DATETIME 配置及会议室预约实现
- 最近验证日期：2026-10-30
- 实现：独立项目 assets/MeetingResource.java 的 time/sqlTime 和时段读写
- 证据：[新业务接入记录](../../MEETING_PROJECT.md)

现象：应用已把北京时间10:00转换成UTC02:00，但使用 Timestamp 参数绑定后，“数据库小时为02:00”的真实验收失败。只验证页面表面时间或变量名无法发现这个偏移。

处理：明确 DATETIME 保存 UTC 的合同；用格式化后的 UTC 日期时间文本作为参数，避免该配置下 Timestamp 的时区再转换；数据库时段比较使用同一合同，SQL DATE_FORMAT 输出北京时间字符串。前端 datetime-local 直接提交本地时间文本，后端按+08:00解释，身份来自登录态。不能同时把前端文本当UTC再加八小时。

验证：同一预约检查原始数据库UTC值、接口北京时间字符串、过去/倒置/秒精度/超过24小时拒绝、相邻区间和并发竞争；交付包部署也需重新执行。此结论针对本次已确认的调用配置，不推断所有 JDBC Timestamp 或所有模板业务都必须用相同写法。模板日志中时间呈现和业务 DATETIME 也应分别验证。
