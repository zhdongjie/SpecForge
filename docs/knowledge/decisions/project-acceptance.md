# D-007 项目定制与外部验收

- 编号：D-007
- 状态：已采用
- 适用范围：新版核心的独立真实项目
- 最近验证日期：2026-10-29
- 实现：[显式验收入口](../../../specforge/acceptance_packs/__init__.py)
- 证据：[回归测试](../../../tests_core/test_external_pack.py)、[工单项目](../../REPAIR_PROJECT.md)

问题：每增加一个真实业务就注册核心应用与内置验收包，会重新让生成器承载全部业务。已有生成→项目定制→verify→package流程却只能选择固定验收名字。

决定：业务资产、重放脚本和验收由独立项目版本管理；核心允许操作者显式传python:module。模块提供规格兼容校验、API验收和浏览器脚本，仍走相同隔离环境、覆盖清单、源码/产物哈希和独立部署检查。业务YAML不能触发Python导入。

代价：开发验收环境必须安装或提供项目模块；定制代码需要项目自己重放，核心不会静默迁移旧定制。验收模块是受信任开发代码，不是可上传的不可信规格，也不是应用部署依赖。

重新评估：多个独立项目重复出现同一能力且已有回归证据时，再考虑提炼通用能力；仅一个项目需要的状态机或页面留在项目内。未来如需接受不可信测试包，应另设计隔离执行，不能把当前显式导入当作沙箱。
