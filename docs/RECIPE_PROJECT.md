# 食谱管理系统首版

## 产品范围

登录后使用。复用模板登录、注册、账号、角色和权限；不开放匿名浏览。普通用户浏览已发布菜谱、搜索和分类筛选、收藏、创建自己的菜谱并提交审核。管理员维护分类、审核他人的菜谱并查看统计。管理员自己的菜谱也须由另一管理员审核。

首版暂不包含评论、点赞、关注、推荐算法、营养分析、部分版本对比。封面支持本人真实 PNG/JPEG 图片上传（最多 5MB，4096×4096），也可填写 HTTPS 图片地址，服务端不抓取远程图片；留空时显示默认封面。用户可自行维护分类，初始化提供家常菜、素食、汤羹、烘焙。

## 业务合同

菜谱状态：草稿 → 待审核 → 已发布 / 已驳回。驳回必须给出原因；作者可修改或重新提交。已发布菜谱编辑保存后转回草稿，立即退出公开列表与收藏列表，重新审核通过后恢复展示。待审核菜谱不能编辑或删除。

菜谱必须包含菜名、分类、至少一项食材和一个步骤；支持 1–40 项食材、1–40 个步骤。菜名最多 80 字符，简介 255 字符，食材名称与用量分别最多 80 字符，每步最多 255 字符。份数 1–100，准备时间 0–1440 分钟。顺序由数组位置确定，食材步骤与主记录在同一事务中保存。

作者身份来自登录态，不接受客户端 author_id 或发布状态。所有编辑、提交、审核和删除携带 revision；过期修订和重复状态转换拒绝，管理员不得自审。详情与明细读取同一事务保护，防止并发编辑泄漏未审核步骤。

收藏采用用户与菜谱联合唯一约束，重复收藏或取消均幂等。撤回或删除的菜谱在收藏列表隐藏；重新发布后仍可恢复原收藏。用户只能管理自己的收藏。

搜索按菜名、简介进行关键词匹配，支持分类筛选和分页；百分号与下划线按文字处理。统计仅管理员可见，包含用户数、已发布数、待审核数、有效收藏数及已发布分类分布。

## 实现边界

新增显式 `application: recipe-management` 扩展。通用核心只负责注册、合同校验和调用；食谱的权限组合、状态流、事务 API 和定制页面由独立应用模块维护。原通用实体接口不授予任何菜谱、食材、步骤或收藏原始表权限，防止绕过审核。分类继续使用通用 CRUD。

本应用规格固定五个实体的存储合同。它不是任意实体字段均能自由修改的通用审核系统；调整此业务合同需同步修改应用扩展、规格与验收。旧版运行时保持冻结，借用与图书规格保持原路径。
