# 第四轮复用：前端上传编排

2026-10-29，状态：已验证。

## 需求与复用决定

| 需求 | 归属与决定 | 证据/验收 |
| --- | --- | --- |
| 文件类型、大小、整批数量校验 | 模板 useFileUpload，调用方显式策略 | 非法整批零请求、重试 |
| 串行上传、加载状态、防重复 | 模板 useFileUpload | 重复调用、部分成功、失败恢复单测 |
| 封面替换、发布权限、公开 URL | 食谱业务保留 | 发布、替换、移除、故障回滚 |
| 私有附件、鉴权读取、解除关联 | 独立工单业务保留 | 私有多图、维修记录、删除和回滚 |
| 控件、预览及错误呈现 | 保留 Vuetify 控件与页面布局 | UI 未抽取成公共组件 |

真实模板具有后端上传、存储、引用与清理能力，但当前没有完整文件管理前端。没有根据后端能力推定存在可直接复用的图片控件。可复用逻辑现归属模板 frontend/src/composables/useFileUpload.ts，不复制到业务资产。生成器不要求无上传业务必须提供该能力。

基准为模板 frontend/src/pages/system/user/UserForm.vue、AddUser.vue；调用方保留 outlined、comfortable、secondary 标题栏、响应式表单与既有预览，未新增主题或另一套上传卡片。新增行为是整批前置校验及并发保护，不改变业务 API、权限、存储和引用合同。

未将功能测试等同于全场景视觉一致性；本轮不宣称建立了自动视觉门禁。

## 验证结果

核心 117 项通过；模板公共队列 4 项通过（真实 Vue ref）。食谱 API 145 项、浏览器 18 项；工单 API 140 项、浏览器 15 项。两者源码与 ZIP 独立部署全部通过，容器和卷已清理。输入清单、交付包哈希与报告位置见 [证据](core-evidence/upload-reuse.json)。

队列测试覆盖非法整批不发送、串行部分成功、失败重试、并发重复调用和回调失败解除状态。浏览器增加类型/大小/数量校验的零请求断言，随后有效图片可上传。现有保存、替换、移除、私有读取、业务故障回滚和权限验收继续通过。

两个生成副本的 useFileUpload 与模板逐字节一致。生成时模板 Git 基线为 63d9fa0，输入清单包含本轮新增公共能力；最终模板提交为 f49d8c9。以输入文件清单和哈希为准。

冻结依赖安装和公共能力测试在生成副本通过；模板所在 Windows 挂载盘的冗余安装耗时过长已停止，不将该次安装记作通过。未增加依赖，锁文件不变。已抽查同主题桌面模板/工单编辑截图和深色手机工单编辑截图；并未新增组件布局，也不宣称完成所有视觉状态认证。

## 当前进度

后端图片校验、文件引用/清理协议、事务接入，以及前端上传编排已统一复用。模板提供公共能力，SpecForge 负责生成接入与验收，工单业务留在独立项目。当前生成交付闭环可复验，但复杂业务仍需项目定制；自动视觉门禁、任意业务的规格自动生成仍未完成。后续优先整理新项目接入流程与能力选择依据，再按实际重复决定抽取，不为减少几行代码扩大公共接口。
