2026-10-28。新版明确规格生成核心的首个独立版本。发布分支为 `codex/core-v0.1.0`；远端 master 的旧运行时分支保持原样，不强制覆盖或混入存在分歧的历史快照。

## 本版交付

- 独立 Python 包和 validate/generate/verify/repair/package/run CLI。
- 明确规格、模板复用、需求覆盖、独立工作区和输入身份追溯。
- 设备、图书、两个字段变体、食谱五套规格通过构建、API、浏览器与独立交付部署。
- 食谱上传与引用生命周期、作者/审核/收藏/统计权限组合。
- 版本化文档知识库、模板UI指南与AI读取要求；食谱与通用CRUD生成资产统一模板风格。
- 97项核心、9项旧入口兼容测试通过。2026-10-28补做人工客户体验，见 [验收记录](../CUSTOMER_ACCEPTANCE_20261028.md)。原五套集成证据的日期为2026-10-27，未冒充当天重跑。

## 获取与使用

```bash
git clone --branch v0.1.0 https://github.com/zhdongjie/SpecForge.git
cd SpecForge
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .
git clone --branch v1.0.3 https://github.com/zhdongjie/springboot3-vue3-vuetify-admin-template.git /your/path/admin-template
python -m specforge run --workspace /your/path/recipe-workspace --spec examples/recipe_management.yaml --template /your/path/admin-template --acceptance-pack recipe-management
```

完整验收需要JDK/Maven、Node/pnpm、Docker与浏览器环境；Windows/WSL使用README中的包装入口。发布wheel只含核心代码与生成资产，样例和指南从本版本源码包获取。采用现代构建工具/隔离环境，旧系统setuptools不足时不要直接跳过构建依赖。

## 边界与已知改进

仅支持全新项目生成，不提供自然语言解析、模型修复或现有数据库增量迁移；复杂真实业务仍需显式规格与项目实现，不承诺任意需求自动覆盖。UI规范不是自动像素一致性门禁。普通用户工作台文案偏管理、管理员还可见模板演示仪表盘、成功操作反馈可进一步加强，作为后续体验改进登记。

数据库、凭据、完整环境文件、截图与原始运行日志不进入发布源码。业务系统生产包保留在本机已验证工作区；此Release附件提供核心wheel、源码zip与校验和，不把五个业务演示数据库打包上传。

发布由仓库原生GitHub Actions使用该仓库自带的GITHUB_TOKEN完成，不读取本机凭据。推送正式标签后才触发；重复标签不覆盖既有版本。详情见 `.github/workflows/release.yml`。
