# SpecForge v0.2.0：仅保留新核心

2026-10-28。按用户明确决定退役旧方案；这是取消旧接口的破坏性变更。

- 从当前代码树移除旧specforge-runtime、内置backend、旧skills及tests_compat，共516个旧跟踪文件。
- 唯一入口为python -m specforge或specforge，明确规格、显式模板和独立工作区合同保持。
- CI不再维护旧入口兼容测试，包发现仅包含specforge命名空间；不保留回退、转发或旧方案开关。
- 默认master通过保留历史的正常合并更新到新核心，不强推、不改写已发布标签。
- 五套规格移除后重新生成，后端/前端/SQL/部署生产文件与已完整集成验收的版本逐文件一致；核心97项通过。
- 外部飞书/dispatcher旧生成源码明确拒绝执行，3项无副作用退役测试通过；没有将自然语言输入静默接到新CLI，也未重启消息服务。

本地旧目录及其未跟踪runs/outputs/数据已经整体移到仓库外私有归档，不随版本上传；新项目工作区、交付包、数据库和演示环境未被清理。历史报告和旧标签保留取证，旧路径不再可执行。

获取当前版本使用master或v0.2.0，按README在虚拟环境安装并提供明确规格与外部模板。旧命令调用方必须停用，不能继续使用原run_requirement_project.py或main.py --auto-build。

本版不增加业务能力，不实现自然语言解析、模型修复或存量数据库迁移。完整退役范围和验证见docs/LEGACY_RETIRED.md及docs/core-evidence/legacy-retirement.json。
