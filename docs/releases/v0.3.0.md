# SpecForge v0.3.0：配套模板与独立业务扩展

2026-10-30。配套后台模板v1.1.0，精确提交与能力路径见源码根目录template-compatibility.json。本文件是发行配套记录，运行时仍使用操作者显式提供的模板路径与能力检查。

## 变化

- 显式 python:module 外部验收包入口，复杂业务和验收可由独立项目维护，不要求每个项目进入核心业务注册表。
- 通用CRUD与食谱使用模板BusinessJdbcContext；食谱图片校验、文件引用/清理协议和前端上传编排复用新模板能力，旧模板缺能力时明确停止。
- 新项目需求覆盖、项目审查材料、阶段声明和独立包验收流程整理；补充时区与事务知识。
- 已用报修工单和新增会议室预约验证独立扩展。工单源码在私有仓库，会议室只保留本地；两者均不随本公共发行附件分发。

核心117项回归；此前各业务的真实API/浏览器/独立部署结果见docs/core-evidence/，会议室源码与独立部署各63项API、10项浏览器、8项需求覆盖。发布时另做发行包安装与配套输入回归，不能用历史报告替代发行物校验。

## 使用与边界

下载wheel安装核心；样例、文档、工具从源码ZIP获得。显式选取模板v1.1.0源码，工作区放到核心、模板和项目源码外。使用步骤见[配套版本](../RELEASE_PAIR.md)、[接入流程](../GENERATION_WORKFLOW.md)。

不实现自然语言解析、模型自动修复、任意业务仅写YAML生成、已交付数据库增量升级或自动视觉门禁。与新核心配套的旧模板不能只看“能编译”就认为兼容；应按能力检查和业务验收升级输入。
