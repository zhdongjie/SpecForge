# 食谱需求覆盖与模板复用审查

## 本次修正

先前将生成器未适配上传错误地当作首版不支持上传，验收只证明了缩减后的范围。这次保留原食谱需求，并明确加入真实图片上传、引用生命周期与权限组合。没有新的功能删减。

需求基线为 [12 项清单](../specforge/applications/recipe_management/assets/requirements.yaml)，不是模板能力白名单。完整实施规则见 [C-006](knowledge/contracts/delivery-coverage.md) 和根 AGENTS.md。

## 模板源码证据与采用方式

| 能力 | 已有模板实现 | 本次复用或适配 |
|---|---|---|
| 登录 / 身份 / 权限 | AuthorizeResource、SecurityUtils、useAuthorities | 直接复用；增加业务动作、作者归属和状态判断 |
| 上传及文件策略 | FileManager、FileUtils、system_file_metadata/type | 直接调用服务，修正生成副本 MIME 策略数据，增加图片专用验证 |
| 文件引用 | FileReferenceService、system_file_reference | 生成副本补 RECIPE_COVER 类型，保存 / 替换 / 移除 / 删除调用引用服务 |
| 事务 | MyBatis-Flex 配置的事务管理器与数据源 | 食谱 JDBC 接入同一上下文；强制引用失败验证回滚 |
| 文件清理 | ClearFileProcess、已存在的定时任务 | 复用原任务，文件行锁后重查引用；实际执行任务验证保留与清理 |
| 部署 | 现有 Compose、JAR、dist 和 uploads 卷 | 复用并做最终交付包独立解压部署验收 |

源模板保持不变。生成副本中的枚举和清理任务改动保存于 `specforge/adaptations/`，附补丁及前后哈希。未知模板结构直接停止，不按名称猜测替换。

## 权限组合

| 账号 / 情况 | 浏览已发布 | 上传封面 | 编辑菜谱 | 审核 | 查看统计 |
|---|---|---|---|---|---|
| 普通作者 | 可以 | 可以 | 仅本人、非待审核、修订匹配 | 不可以 | 不可以 |
| 管理员 | 可以 | 可以 | 仍仅本人、非待审核 | 仅他人待审且修订匹配 | 可以 |
| 只读账号 | 可以 | 不可以 | 不可以 | 不可以 | 不可以 |
| 仅通用文件上传权限 | 不自动获得食谱权限 | 不可以调用食谱封面接口 | 不可以 | 不可以 | 不可以 |
| 无食谱权限 / 未登录 | 不可以 | 不可以 | 不可以 | 不可以 | 不可以 |

上传文件本身不等于可被任意用户关联；本地图片必须存在且由当前作者上传，绝对 URL 不能伪装系统文件路径绕过校验。重复收藏、管理员自审、其他作者写入、状态与修订冲突仍执行原验收。

## 交付门禁

构建、API、浏览器通过后，覆盖检查逐项匹配清单和实际证据；任何缺项均 FAIL。交付包保存清单及其哈希，独立部署再验一次。不把构建通过或测试数量当作需求完整的证明。历史样板未声明 application 的兼容入口保持原行为。


自动兼容例外仅限已有四个固定样板项目标识：device_borrow、book_lending、book_fields_v1、book_fields_v2。其他新项目即使未使用 application 扩展，也必须提供需求覆盖清单才能完成验收和发布；生成或 build-only 诊断不代表交付完成。


## 当前验证结果

核心单元测试 97 项、旧入口兼容测试 9 项通过。正式生成运行 `20261024T084208-3332aa0829` 的构建、API、浏览器和 12 项需求覆盖通过；交付包独立部署完成 145 项 API 检查、13 个浏览器步骤、12 项覆盖检查，另补验真实 JPEG 的替换及清理。

模板源码清单与修复前完全一致；副本适配前后哈希匹配实际文件。临时容器、卷、网络、触发器及解压目录已清理；没有持续运行的验收实例。完整包路径、规格身份、模板身份、清单哈希及结果见 [修复证据](core-evidence/recipe-reuse-fix.json)。需求门禁核对声明清单与执行证据，并不自动证明自然语言需求完整，实施和交付前仍须审阅原始需求。


文件访问边界：本次授权检查覆盖上传、关联、菜谱正文和业务操作；图片访问沿用模板的静态文件 URL 模型，不宣称提供私有文件下载授权。需要私有附件时，应作为明确的新需求设计下载接口或签名访问，不能把菜单权限当作文件访问控制。
